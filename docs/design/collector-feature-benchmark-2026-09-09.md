## Concrete failure cases to give Claude

- `MyTasks.tsx` treats `claims.data === undefined` as loading even after failure. No error/retry branch; title lookup failure can show IDs although API already serves names.
- `SessionCreate.tsx` renders loading/failed claims/tasks/devices as zero data and tells collectors to claim/bind again. `create.isError` is not displayed and `create.isPending` does not lock the action. Retrying the same declaration retains its request ID in memory; do not break that contract.
- `Devices.tsx` omits list loading/error states, bind-pending lock and localized refusal mapping. Showing a form next to unknown device state must not imply no devices exist.
- `Agreements.tsx`, `Training.tsx`, `Exam.tsx` omit mutation failure and pending feedback. Do not strand a collector after consent/training submission loses signal.
- `App.tsx` keeps the token on network failure, correctly, but routes cold-start failure to registration. Present a recoverable signed-in loading/error state; a returning collector should not be told to register again because the server is unreachable.
- `TaskHall`, `Income`, `Uploads` show read errors only in their empty component. A failed refresh with cached rows needs a stale/error notice; current `ListScreen` exposes no refresh control. Preserve prior data explicitly as stale rather than silently authoritative.
- `Income.tsx:lifecycle` marks “under review” done for every returned entry, including an uploaded-only state. Derive each event from an explicit server fact; a timeline is not decorative completion.

## Native responsiveness handoff — not yet measured

`ui.tsx` already reserves bottom-tab overhang in scroll content; do not regress it. Safe-area helpers still estimate bottom chrome from screen/window height and have no native cutout/rotation observer. Native fonts are not linked; browser font appearance is not proof of Android rendering. Tabs use single-line labels and the reserved bar height assumes a fixed row, so enlarged text deserves native measurement.

Claude should inspect Android widths 320/360/390/412 dp, short 640 dp height, gesture and three-button navigation, portrait/landscape, keyboard open, and 100/130/200% text size. Require readable Vietnamese diacritics and Chinese labels; no clipped payment values; final action fully above tabs/system bars; accessible touch regions; error recovery without data loss. Validate real Android separately from React Native Web. Idle native motion must stop when offscreen/backgrounded and obey Remove animations. No animation may imply recording, uploading or payment success.

Recommended production decision: ship an honest staffed pilot flow while hardware transfer and approved content remain unresolved. Do not describe the native collector as production-ready solely because website rhythm or source tests pass.
